Both assigned headlines pass the two final focused runs. **No additional
row-specific library change is retained.** This is not all-39 completion evidence
and does not demonstrate a library speedup.

## Source and workload

Branch `t3/optimize-row-replacement`; measured final source `03f8f01` has the same
tree as merged main `f1accbb`. It includes frame alignment `4a11a3d`, owned Chrome
profile cleanup `2e54065`, wheel CSS, and geometry cache `0ed8a4a`.
The shared geometry cache is reused without a duplicate implementation.

`scenarios.ts`, `datasets.ts`, and `index.ts` use 10,000 x 20 cells. Both scenarios
focus row 5005 and commit `preserved-edit` before measurement. Reorder reverses
copied values and stable IDs. Insert/delete inserts 100 rows at index 5000, then
restores the original matrix. Each adapter submission starts inside rAF and ends
at the second subsequent callback; the insert/delete headline is the median of
per-sample sums of both steps. Dataset creation, setup editing and every-cell
read-back are outside the timed intervals. Peculiar updates controlled signals
and reconciles in Solid's flush; Handsontable copies rows and calls updateData.
No workload, API, ownership, selection, history or formula contract was changed.
